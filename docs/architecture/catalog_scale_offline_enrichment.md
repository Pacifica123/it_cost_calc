# Масштабируемый staging каталога и автономное обогащение

## Цель

Каталог поставщика может содержать десятки тысяч строк. Расчётная часть должна сохранять полный набор альтернатив, но GUI не должен материализовывать десятки тысяч Qt-строк и полный staging JSON при каждом открытии экрана.

## Поток данных

```text
XLSX / CSV / feed
        |
        | streaming read + optional scope
        v
canonical catalog staging JSON (schema v3)
        |                         |
        | full computation path   | disposable projection
        v                         v
GA / AHP / import ТО        SQLite UI read-model
                                  |
                                  | LIMIT/OFFSET + search/filter
                                  v
                              Qt, 100-1000 rows/page
```

`catalog_staging.json` остаётся переносимым и авторитетным состоянием. `catalog_staging.ui.sqlite3` — только воспроизводимая read-model: она строится после сохранения staging, не входит в репозиторий и может быть удалена в любой момент.

## Оптимизации масштаба

- CSV и XLSX читаются потоково; XLSX использует `ElementTree.iterparse`, а не разворачивает worksheet XML целиком.
- Для пробных запусков доступен необязательный scope 1k/5k/10k/25k; полный режим остаётся значением по умолчанию.
- Тяжёлый staging и локальное обогащение запускаются отдельным процессом, чтобы не блокировать event loop Qt.
- Staging schema v3 не хранит повторно вычислимые `catalog_item`, validation и single-source federation mirrors.
- Одноисточниковая федерация не создаёт глубокую копию исходного наблюдения.
- GUI запрашивает только проекцию страницы из SQLite; поиск и сводные счётчики также выполняются в SQLite.
- Детальная карточка одной строки восстанавливается из compact JSON одной записи в read-model, поэтому открытие карточки не требует загрузки всего staging.

## Цена и характеристики supplier feeds

Нормализатор распознаёт расширенный набор русских заголовков и имеет безопасный scored fallback для ценовых колонок (`Цена с НДС`, `Цена партнёра`, `РРЦ`, `Оптовая цена` и близкие варианты). Из названия и исходных полей извлекаются только явно присутствующие RAM, CPU cores, storage, power и сетевые метрики.

## Автономное обогащение

Icecat остаётся опциональным источником. Для демонстрации без аккаунта и сети есть отдельное `offline-heuristic-v1`:

1. извлекает явные признаки из исходной строки;
2. при разрешении пользователя заполняет отсутствующие метрики консервативным профилем категории;
3. при разрешении пользователя строит детерминированную демонстрационную цену, если реальной цены нет.

Оценочные значения имеют low confidence, отдельный provenance и `price_kind=estimated_price`. Реальная supplier/quote цена никогда не заменяется оценочной.

## Ограничения

SQLite read-model оптимизирует чтение GUI, но операции, меняющие весь каталог (refresh federation, массовое enrichment), по определению работают с полным набором альтернатив. Они вынесены в worker process. Read-model не является источником истины и не должна использоваться напрямую для GA/AHP/NPV.
