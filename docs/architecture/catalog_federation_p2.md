# Федерация каталога и ценовые наблюдения (P2)

## Цель

P1 научил приложение получать структурированные feeds. P2 устраняет предположение
«одна строка источника = один независимый товар». Теперь staging собирает один
проверяемый товар из нескольких независимых наблюдений поставщиков.

```text
supplier A ─┐
supplier B ─┼─> normalize -> identity federation -> CatalogItem
supplier C ─┘                                  ├─ identity
                                               ├─ offers[]
                                               ├─ effective offer
                                               └─ price_summary
```

DNS/Yandex legacy collectors не участвуют в этом контракте специально: федерация
работает над нормализованными строками независимо от способа получения данных.

## Идентичность

Объединение выполняется только по строгим ключам в таком порядке:

1. `GTIN`;
2. `brand + MPN`;
3. `brand + model`.

Одного совпавшего названия недостаточно. Нормализация ключей игнорирует регистр,
пробелы и разделительную пунктуацию. Транзитивные совпадения поддерживаются:
например, один источник может связать GTIN с MPN, а другой — тот же MPN с моделью.

Метаданные результата находятся в `catalog_item.federation`:

- `identity_key`, `identity_kind`;
- `matched_by`;
- `sources`, `source_count`;
- `observation_count`, `offer_count`;
- `identity_conflicts`, `category_conflicts`;
- `observation_keys` для сохранения ручной проверки при refresh.

## PriceObservation

`CatalogItem` сохраняет обратную совместимость через поле `offer`, но дополнительно
имеет `offers[]`. Каждое наблюдение хранит:

- `source`, `source_name`, `source_product_id`;
- `price`, `currency`, `price_kind`;
- `availability`;
- `url`, `region`;
- `observed_at`;
- стабильный `offer_id`;
- рассчитанную `freshness`.

`price_summary` содержит количество наблюдений и источников, `min/median/max` в RUB,
границы времени и источник эффективного предложения.

## Выбор effective offer

Политика детерминирована:

1. только положительная цена в RUB;
2. предложение в наличии выше неизвестного и отсутствующего;
3. выше приоритет типа цены:
   `commercial_quote > supplier_price > retail_offer > contract_price >
   procurement_benchmark > historical_price > estimated_price`;
4. внутри одного типа — более свежее `observed_at`;
5. последняя развязка — меньшая цена.

P5 уточняет семантику: реальное коммерческое предложение считается более
доверенным наблюдением, чем более свежая розничная витрина. ЕИС benchmark при
этом не помещается в `offers[]` вообще и используется только как независимая
статистика.

Свежесть:

- `fresh` — до 30 дней;
- `aging` — 31–90 дней;
- `stale` — старше 90 дней;
- `unknown` — время наблюдения отсутствует/некорректно.

Staging предупреждает о stale effective price и конфликтах identity/category.

## Refresh источника

`CatalogStagingService.stage_file()` теперь означает «обновить один источник»,
а не «заменить весь staging этим файлом».

При обновлении:

1. старые наблюдения только этого source удаляются;
2. остальные источники сохраняются;
3. новый feed добавляется;
4. федерация перестраивается;
5. существующий `staging_id`, ручные overrides и review сохраняются по пересечению
   source-observation keys.

Если источник перестал содержать товар, удаляется только его наблюдение. Сам
федеративный товар остаётся, пока его подтверждает хотя бы один другой источник.

## Runtime

После подтверждения в ТО передаются:

- выбранная `offer` как текущая цена расчёта;
- все `offers`;
- `price_summary`;
- `federation`;
- прежние `identity`, provenance и manual overrides.

Поэтому GA/AHP/NPV продолжают работать со скалярной ценой без изменения своего
контракта, но отчёты и последующие этапы могут видеть происхождение и диапазон цены.

## Ограничения P2

- история цен внутри одного источника пока не накапливается: refresh заменяет его
  текущее наблюдение;
- автоматическая оценка доверия к поставщику ещё не вводится;
- спецификации исходных supplier feeds по-прежнему объединяются консервативно.
  P3 добавляет отдельный Icecat enrichment поверх федерации; см.
  `docs/architecture/catalog_enrichment_p3.md`.
